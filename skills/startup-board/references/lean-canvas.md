# Lean Canvas (Ash Maurya format)

Fill from what the founder actually knows or has evidence for. Mark anything guessed as **[assumption — untested]** rather than presenting a guess as a fact; the canvas is only useful if it's honest about what's real vs. hypothesized.

| Block | What goes here |
|---|---|
| **Problem** | Top 1–3 problems, and how customers solve them today (existing alternatives) |
| **Customer Segments** | Target customers, and early adopters specifically (the narrowest slice most likely to want this now) |
| **Unique Value Proposition** | Single, clear, compelling message that states why you're different and worth paying attention to |
| **Solution** | Top 1–3 features/capabilities that address the top problems (keep minimal — this isn't a feature list) |
| **Channels** | Path to customers — organic, paid, partnerships, direct outbound |
| **Revenue Streams** | Revenue model, pricing, lifetime value estimate |
| **Cost Structure** | Customer acquisition costs, distribution costs, hosting/build costs, people costs |
| **Key Metrics** | The few numbers that tell you if this is working (tie to the current Fit stage — see fit-framework.md) |
| **Unfair Advantage** | Something that can't easily be bought or copied — not "we'll execute faster," a real moat (proprietary insight, network effects, existing audience, unique data) |

## Output format
Render as a markdown table or a 3x3 grid layout matching the classic canvas shape, one short bullet list per block (not paragraphs). Follow it with a 2–3 line "biggest gaps" note calling out which blocks are mostly assumptions and need testing first.
