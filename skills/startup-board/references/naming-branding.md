# Naming, Branding & Domain

Only run this phase on request — it's easy to bikeshed on names before the idea is validated, and the board's job is to prevent exactly that.

## Naming approach

Generate names from the actual UVP and category, not generic startup-name patterns. Offer a spread across a few styles rather than 20 similar variations:
- **Descriptive**: names a real word/concept close to the function.
- **Compound/invented**: blend of two relevant words.
- **Abstract/metaphor**: evokes the feeling/outcome rather than the mechanism.

For each name offered, note: does it work said aloud, is it easily spelled from hearing it, does it avoid an unintended meaning in an obvious other language, does it avoid confusion with an existing well-known brand.

## Domain & handle check

State plainly that live availability must be checked (a quick web_search or the founder checking directly) before committing — never assert a domain is available without checking, since this changes based on real-time data.

## Tagline

One short line under the name, tied to the positioning statement from `gtm-launch.md` — not a generic mission statement.

## Output format
A short table: Name | Style | Why it fits | What to verify (domain/trademark) — plus one recommended pick with reasoning, not just a flat list with no opinion.
